## Critical Bugs Fixed

### 1. Database Persistence Bug
**File**: `src/infrastructure/db/repositories/application_repo.py`

**Issue**: Application state was not being persisted to database. Phase transitions and state snapshots were lost after each request.

**Root Cause**: Repository methods used `flush()` instead of `commit()`:
```python
# BEFORE (broken)
async def update(self, application: Application) -> Application:
    await self.session.merge(application)
    await self.session.flush()  # ❌ Only flushes to session, not committed
    await self.session.refresh(application)
    return application
```

**Fix**: Changed to `commit()` in both `update()` and `save_state()` methods:
```python
# AFTER (fixed)
async def update(self, application: Application) -> Application:
    await self.session.merge(application)
    await self.session.commit()  # ✅ Commits to database
    await self.session.refresh(application)
    return application
```

**Impact**: All phase transitions and state snapshots now persist correctly.

---

### 2. Resume State Update Bug
**File**: `src/services/agent_runner.py`

**Issue**: When resuming from interrupt (e.g., after document upload), uploaded files were not included in the graph state, causing document collection to fail.

**Root Cause**: `Command(resume=...)` only passed the resume value, not state updates:
```python
# BEFORE (broken)
result = await graph.ainvoke(
    Command(resume=user_input),  # ❌ Missing uploaded_files
    config=config
)
```

**Fix**: Added `update` parameter to include uploaded_files:
```python
# AFTER (fixed)
result = await graph.ainvoke(
    Command(
        resume=user_input,
        update={"uploaded_files": uploaded_files}  # ✅ Include state update
    ),
    config=config
)
```

**Impact**: Documents uploaded during interrupt resume are now properly tracked and processed.

## Remaining Issues

### 1. Documents Table Empty (Medium Priority)
**Symptom**: The `documents` table remains empty even though documents are uploaded and processed.

**Root Cause**: Document records are created in `document_collection_node` (stored in graph state) but not persisted to the database.

**Current Flow**:
1. Documents uploaded → saved to `data/uploads/{application_id}/`
2. Document metadata stored in graph state (`uploaded_documents`)
3. Extraction results stored in graph state (`extraction_results`)
4. ❌ Document records NOT created in `documents` table

**Expected Flow**:
1. Documents uploaded → saved to disk
2. Document records created in `documents` table
3. Extraction results linked to document records
4. Graph state references document IDs

**Fix Required**: Add database persistence in `document_collection_node`:
```python
# In src/agents/orchestrator/phases/document_collection.py
for doc_entry in new_doc_entries:
    document = await document_repo.create(
        application_id=application_id,
        document_type=doc_entry["document_type"],
        file_path=doc_entry["file_path"],
        file_name=Path(doc_entry["file_path"]).name,
        file_size=Path(doc_entry["file_path"]).stat().st_size,
        upload_timestamp=datetime.now(timezone.utc)
    )
    doc_entry["document_id"] = str(document.id)
```
